# Amaal Deployment Hardening — 2026-10-05

This release addresses the deployment failures and the delivery-path race discovered during the forensic review.

## Implemented

1. `/reset-password` is now split into a server page plus client content behind `Suspense`, matching the working `signup` and `access-pending` pattern. This removes the confirmed Next.js prerender failure from `useSearchParams()`.
2. Vercel uses a version-controlled `ignoreCommand` so a ZIP-only upload commit is skipped while a real source-sync commit still builds.
3. Vercel install is lockfile-first: `npm ci` when `apps/web/package-lock.json` exists, with an npm fallback when it does not. Lifecycle scripts are disabled for the deployment install.
4. Render API, worker, and intelligence services use `autoDeployTrigger: checksPass` and build filters. ZIP-only upload commits therefore do not trigger application builds, while source and shared-package changes do.
5. Render health-check paths are aligned with the source configuration: API `/ready`, worker `/health`.
6. Render production configuration contains no pnpm install/start/build path.
7. Local pnpm workspace metadata remains safe for pnpm 11+: `core-js` is explicitly permitted through `allowBuilds`, while production remains npm-only.
8. ZIP sync now uses an allow-list for approved GitHub Actions workflows (`zip-sync.yml`, `ci.yml`, `generate-lockfiles.yml`) and rejects staged ZIP artifacts before committing.
9. ZIP sync creates the root npm lockfile and the web-app npm lockfile in the normalized repository, then validates the web lockfile with `npm ci`.
10. CI now generates a missing root lockfile when needed and installs from the lockfile with `npm ci`.
11. Deployment forensic auditing now checks the delivery controls above, the reset-password Suspense boundary, workflow allow-list, and ZIP-artifact hygiene.
12. Repository runtime caches and Python bytecode artifacts were removed from the release tree.

## ZIP-upload deployment race hardening

The GitHub ZIP upload is an intermediate repository state. The Vercel ignored-build step now refuses to build any checkout that still contains a ZIP deployment artifact. ZIP-sync extracts, validates, removes the ZIP, and creates the normalized `[deploy-ready]` commit. The normalized commit contains no ZIP artifact, so Vercel proceeds normally. This prevents a successful deployment of an incomplete pre-sync snapshot.

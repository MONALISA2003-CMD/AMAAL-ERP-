# Amaal ERP — Phase 3: Products, IMEI & Inventory Custody

**Status:** Implemented in repository; production schema application remains a release gate.
**Date:** 3 October 2026

## Phase objective

Phase 3 establishes the operational product and physical-device custody layer in Neon. Product master data is distinct from individual IMEI units. Every physical unit has an auditable movement history and an authoritative current custody scope.

## Implemented

- Brand, product model and variant/SKU catalog services with transactional audit/outbox events.
- 15-digit IMEI validation and batch receipt controls.
- Secondary IMEI uniqueness protection.
- Master and regional warehouse reads and receipt flow.
- IMEI custody fields for holder, region, team and shop.
- Allocation state machine integration: request → approve → dispatch → receive, plus cancellation/rejection and warehouse return.
- Movement ledger now records holder, warehouse, region, team and shop endpoints.
- Current-custody read projection with holder, manager, team leader, team, shop and aging fields.
- Scoped inventory reads through the Amaal authorization boundary.
- Inventory operations are idempotent at the API boundary and emit audit/outbox records.
- Product/inventory permissions are explicitly seeded for the authorization layer.

## Identity authority inside Phase 3

The Amaal login-creation hierarchy is explicit and enforced in both the organization control plane and the invitation database trigger:

**CEO → Admins → Regional Managers / Managers / Team Leaders / Agents / Shop Owners**

The CEO is the only role allowed to create or invite an Admin. Admins can create/invite Regional Managers, Managers, Team Leaders, Agents and Shop Owners. Admins do **not** directly recruit Recovery Officers; Recovery Officers remain a Regional Manager-controlled role.

The invitation flow creates a controlled invitation record. The invited person completes their own Neon Auth account creation rather than receiving a plaintext password generated by another employee.

## Custody rules

Warehouse states are warehouse-only. Manager state is holder-only. Agent state requires holder + team. Shop Owner state requires holder + team + shop. SOLD stock cannot retain operational custody fields. Team and shop must belong to the current region/team respectively.

Completed movement history is append-only from the application perspective. Corrections, reversals and write-offs create new records rather than mutating history.

## Aging

Phase 3 exposes current aging data using the configured default bands: 1–7 green, 8–13 orange, 14–17 red, 18+ dark-red. The policy engine and suspension/recovery escalation remain Phase 5 responsibilities.

## Release gate

Phase 3 database foundations are applied to production Neon. The remaining release gates are exact GitHub source synchronization, clean-workspace CI, exact Render/Vercel deployment from this source, and end-to-end production workflow verification.
